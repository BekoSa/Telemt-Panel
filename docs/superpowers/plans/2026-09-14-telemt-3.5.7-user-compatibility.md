# Telemt 3.5.7 User Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Align the existing dashboard/user UI with Telemt 3.5.7 readiness and current user-control endpoints while retaining clear behavior against older servers.

**Architecture:** Keep the existing transparent `/api/v1/*` server proxy. Extend only the browser UI and its source-contract tests: readiness is an optional GET capability, while user mutations use the current Telemt routes and refresh the selected user after successful operations. A 404/405 is surfaced as an unsupported-server error rather than the obsolete hard-coded rotate-secret warning.

**Tech Stack:** Existing React 18 UMD SPA, existing `api()` helper, Node `node:test` source-contract tests.

**Spec:** `docs/superpowers/specs/2026-09-14-telemt-3.5.7-modernization-design.md`

## Global Constraints

- Keep Telemt credentials server-side through the existing proxy.
- Do not introduce Express 5 or a frontend build-system migration in this phase.
- Do not assume readiness exists on legacy Telemt: absence must display as unavailable/unsupported rather than breaking the dashboard.
- Mutating user actions must use existing CSRF handling in `api()`.
- Disable/reset operations require confirmation before the request is sent.
- Remove the April-era special-case text claiming rotate-secret is unavailable.

### Task 3: Replace the legacy rotate workaround and add user controls

**Files:**
- Modify: `public/index.html`
- Test: `test/ui-contract.test.js`

**Interfaces:**
- Consumes:
  - `POST /v1/users/{username}/rotate-secret`

  - `POST /v1/users/{username}/disable`
  - `POST /v1/users/{username}/reset-quota`
- Produces: `runUserAction()` UI helper and current user state refresh.

- [ ] **Step 1: Replace rotate-only operation state**

Use one `busyAction` and one operation message instead of a rotate-specific boolean/message so all four controls share consistent disabled/error state.

- [ ] **Step 2: Implement `runUserAction(action, successMessage)`**

Call `api('/users/'+user.username+'/'+action, 'POST', {})`, then refresh with `GET /users/{username}` and update modal state. If Telemt returns `not_found`/`method_not_allowed`, report that the action is unsupported by the connected Telemt version; otherwise show the upstream error unchanged.

- [ ] **Step 3: Wire controls**

Keep rotate-secret, add enable/disable according to `user.enabled`/`user.disabled` data when available, and add reset-quota. Require `window.confirm()` before disable and reset-quota.
